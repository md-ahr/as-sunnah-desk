# 13 · Next.js 16 Reference

Next.js 16 changed enough that code written from memory of 14 or 15 will either fail to build or silently miss the version's capabilities. This is a working reference for the APIs this project uses, verified against the documentation bundled at `node_modules/next/dist/docs/` for the installed version (16.3.5).

The bundled docs are the authority. When something here disagrees with them, they win — and if the version changes, re-verify rather than trusting this page.

## Breaking changes that affect this project

### `middleware.ts` → `proxy.ts`

```ts
// src/proxy.ts   (inside src/ when using a src directory)
import { NextResponse, type NextRequest } from 'next/server'

export function proxy(request: NextRequest) { /* ... */ }

export const config = { matcher: ['/((?!_next/static|favicon.ico).*)'] }
```

- File and exported function are both `proxy`.
- **Runtime is Node.js and cannot be configured.** The Edge runtime is not supported.
- Config flags renamed: `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`.
- `fetch` cache options have no effect here.
- Only one proxy file per project; split logic into modules and import them.

### `params` and `searchParams` are Promises

Synchronous access is fully removed — there is no compatibility fallback as there was in 15.

```tsx
export default async function Page(props: PageProps<'/requests/[id]'>) {
  const { id } = await props.params
  const query = await props.searchParams
}
```

Also async: `cookies()`, `headers()`, `draftMode()`, and `params` in `route.ts`, `layout.tsx`, `default.tsx` and the metadata image conventions.

### Generated global type helpers

`PageProps`, `LayoutProps` and `RouteContext` are **globally available and must not be imported**. They are generated by `next dev`, `next build`, or `next typegen`.

```tsx
function Page(props: PageProps<'/requests/[id]'>) {}
function Layout(props: LayoutProps<'/requests'>) {}
export async function GET(_req: NextRequest, ctx: RouteContext<'/api/requests/[id]'>) {}
```

**Consequence for CI:** run `next typegen` before `tsc --noEmit`, or typechecking fails on types that are actually correct.

### `revalidateTag` requires two arguments

```ts
revalidateTag('posts')            // deprecated — raises a TypeScript error
revalidateTag('posts', 'max')     // correct
```

The second argument is a `cacheLife` profile, or `{ expire: N }`.

### `next lint` removed

Run ESLint directly. The `eslint` key in `next.config.ts` is removed, and `next build` no longer lints.

### Turbopack is the default

No `--turbopack` flag needed for `dev` or `build`. A custom `webpack` config now **fails** the build unless you pass `--webpack`.

`next dev` outputs to `.next/dev`, so `dev` and `build` can run concurrently. A lockfile prevents two dev servers on one project.

### Other removals worth knowing

| Removed | Replacement |
|---|---|
| `experimental.ppr`, `experimental_ppr` | `cacheComponents: true` |
| `experimental.dynamicIO`, `experimental.useCache` | `cacheComponents: true` |
| `unstable_cache` | `use cache` |
| `unstable_noStore()` | `connection()` + `<Suspense>` |
| `unstable_rootParams` | `next/root-params` |
| `serverRuntimeConfig`, `publicRuntimeConfig` | Environment variables |
| `next/legacy/image` | `next/image` |
| `images.domains` | `images.remotePatterns` |
| AMP support | — |

Parallel route slots now require an explicit `default.js`, or the build fails.

## Cache Components

Enabled with `cacheComponents: true`. This makes **Partial Prerendering the default** and turns on the `use cache` family.

### The three directives

| Directive | Server storage | Scope | Can read cookies/headers? |
|---|---|---|---|
| `'use cache'` | In-memory or a cache handler | Shared across users | **No** — throws |
| `'use cache: remote'` | Remote handler (Redis/KV) | Shared across users | **No** |
| `'use cache: private'` | **None** | Per client, browser memory | **Yes** |

`connection()` is prohibited inside all three.

Placement rules: first statement in an async function or component; at file top makes every export cached (and every export must be async); **cannot be used directly in a Route Handler body** — extract a cached helper.

Cache keys are composed from the build ID, a hash of the function's location and signature, and the serialised arguments. Variables captured from an outer scope are bound as arguments automatically.

**Cache keys and `cacheTag` values are stored in plain text, unhashed** — in the default in-memory cache and in any remote handler. Key on stable identifiers, never on emails, tokens or personal data.

### `cacheLife` profiles

| Profile | `stale` | `revalidate` | `expire` |
|---|---|---|---|
| `default` | 5 min | 15 min | never |
| `seconds` | 30 s | 1 s | 60 s |
| `minutes` | 5 min | 1 min | 1 h |
| `hours` | 5 min | 1 h | 1 day |
| `days` | 5 min | 1 day | 1 week |
| `weeks` | 5 min | 1 week | 30 days |
| `max` | 5 min | 30 days | 1 year |

Thresholds that cause silent behaviour changes:

- The client router enforces a **30-second minimum** `stale`, regardless of configuration.
- `stale < 30s`, `revalidate: 0`, or `expire < 5 min` → **excluded from prerenders**.
- `stale ≥ 5 min` → included in the **App Shell** (every preset except `seconds` qualifies).

A short-lived inner cache inside an outer `use cache` that has no explicit `cacheLife` is a **build error** during prerendering.

`cacheLife` cannot be called at module scope, and only one call takes effect per invocation.

### `cacheTag`

```ts
cacheTag('request:142', 'facet-counts')
```

Up to 128 tags per call, 256 characters each, case-sensitive, idempotent. Only valid inside a `use cache` scope.

### Invalidation

| API | Callable from | Semantics |
|---|---|---|
| `updateTag(tag)` | **Server Actions only** | Expires immediately; next read waits for fresh data (read-your-writes) |
| `revalidateTag(tag, profile)` | Actions + Route Handlers | Stale-while-revalidate |
| `refresh()` | **Server Actions only** | Refreshes the client router |
| `revalidatePath(path, type?)` | Actions + Route Handlers | Path-based; prefer tags |

Calling any of these from a Server Action clears the client cache immediately, bypassing stale windows.

### Route segment config under `cacheComponents`

**These now error:** `dynamic`, `revalidate`, `fetchCache`, `dynamicParams`, `runtime = 'edge'`, `experimental_ppr`.

**These are new:**

```ts
export const instant = false              // allow this segment to block; opts out of validation
export const prefetch = 'partial'         // 'auto' | 'partial' | 'force-disabled'
```

`instant = false` does **not** clear synchronous-IO build errors.

`generateStaticParams` returning `[]` is an error — it must return at least one param.

### What triggers a build error

Under `cacheComponents`, these fail unless wrapped:

- Uncached data access outside `<Suspense>`
- `cookies()`, `headers()`, `searchParams`, or dynamic `params` outside `<Suspense>`
- `Date.now()`, `new Date()`, `Math.random()`, `crypto.randomUUID()` during prerendering

The fixes: wrap in `<Suspense>`, wrap in `use cache`, or call `connection()` first for genuinely per-request values.

**Synchronous I/O is treated as a predictable value** and prerendered — including `better-sqlite3` and `node:sqlite`. For per-request data from a synchronous source you must call `connection()` first. This project avoids the whole class by using an async driver.

## Errors

### File conventions

| File | Notes |
|---|---|
| `error.tsx` | Must be `'use client'`. Props: `error`, `retry`, optional `reset` |
| `global-error.tsx` | Must render its own `<html>` and `<body>` |
| `not-found.tsx` | Rendered by `notFound()` |
| `forbidden.tsx` / `unauthorized.tsx` | Require `experimental.authInterrupts: true` |
| `global-not-found.js` | Requires `experimental.globalNotFound: true` |

`retry` is stable as of 16.3.0 (previously `unstable_retry`). It re-fetches and re-renders, where `reset` only clears the error.

### `catchError`

Stable in 16.3.0, for component-level boundaries inside a page:

```tsx
import { catchError, type ErrorInfo } from 'next/error'

function Fallback(props: { title: string }, { error, retry }: ErrorInfo) { /* ... */ }
export default catchError(Fallback)
```

It is framework-aware: `redirect()` and `notFound()` pass through rather than being swallowed.

### Functions

From `next/navigation`: `notFound()`, `redirect(path, type?)`, `permanentRedirect()`, and — behind `authInterrupts` — `forbidden()`, `unauthorized()`.

All throw and return `never`. **Never wrap them in `try/catch`**; use `unstable_rethrow` if you must catch nearby.

**PPR consequence:** once the static shell starts streaming the status is already 200 and cannot change. `notFound()` inside a Suspense boundary renders not-found UI with a 200 status. For a real 404/401/403 status code, perform the check in `proxy.ts` before streaming.

## Server Functions and Actions

Terminology: a **Server Function** is any `'use server'` async function; a **Server Action** is one invoked through a React action mechanism.

```ts
'use server'
export async function updateStatus(input: unknown) { /* ... */ }
```

Automatic protections: `POST`-only, CSRF via `Origin`/`Host` comparison, encrypted non-deterministic action IDs, unused actions stripped from the client bundle, 1 MB body limit.

**Your responsibility:** authentication, authorization, input validation, and constraining return values. Actions are reachable by direct `POST` even when nothing links to them, and page-level auth does not extend to them.

**Actions are dispatched sequentially, one at a time per client.** Do not use them for parallel data fetching — use Server Components or a Route Handler.

### React hooks

```tsx
const [state, formAction, pending] = useActionState(action, initialState)
// With useActionState the action's first parameter becomes the previous state:
//   async function action(prevState, formData) {}

const { pending } = useFormStatus()              // from react-dom, in a child of the form
const [optimistic, setOptimistic] = useOptimistic(serverValue)
```

`useOptimistic` reverts automatically when the transition ends. A throw inside `useTransition` surfaces in the nearest error boundary.

## Route Handlers

```ts
export async function GET(_req: NextRequest, ctx: RouteContext<'/api/requests/[id]'>) {
  const { id } = await ctx.params
  return Response.json({ id })
}
```

Methods: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`. Others return 405. `OPTIONS` is auto-implemented if omitted.

Not cached by default. Under Cache Components, `GET` follows the same prerendering model as pages and can be prerendered when it touches no runtime data.

The docs advise: do **not** call Route Handlers from Server Components (extra round-trip, and it fails during prerendering) — query the source directly.

## Prefetching

`<Link prefetch>` accepts `"auto"` (default), `true`, `false`. Prefetching happens in **production only**.

With `partialPrefetching: true` (16.3.0+, requires `cacheComponents`), the router prefetches each route's **App Shell** — the render that does not depend on the link's URL. Routes reading `cookies()` produce a per-session shell cached on the client.

`prefetch={true}` costs **one server invocation per visible link**. A grid of 25 links with `prefetch={true}` issues 25 prefetch renders.

## Data fetching

- Identical `fetch` calls in one tree are memoised automatically.
- `fetch` is **not** cached by default.
- For non-`fetch` sources use `cache()` from `react` for request-scoped deduplication.
- Each `use cache` boundary has an isolated `React.cache` scope.
- Pass an unawaited promise to a Client Component and unwrap with `use()`, inside `<Suspense>`.
- `Promise.all` fails wholesale; use `Promise.allSettled` for partial tolerance.

## Configuration used by this project

```ts
const nextConfig: NextConfig = {
  reactCompiler: true,        // stable in 16
  cacheComponents: true,      // use cache + PPR
  partialPrefetching: true,   // requires cacheComponents
  typedRoutes: true,          // stable; was experimental.typedRoutes
  experimental: {
    optimizePackageImports: ['lucide-react'],
  },
}
```

`serverExternalPackages` (top-level, not experimental) opts packages out of server bundling if a native dependency needs it.

## Other version-specific details

**`useSearchParams`** in a prerendered route client-side-renders the tree up to the nearest `<Suspense>`. A static page using it without a boundary **fails the production build** — and the dev server hides this, because routes render on demand.

**Updating search params** without a reload: `router.replace(url, { scroll: false })`, or `window.history.replaceState`, which integrates with the Next.js router.

**Layouts do not receive `searchParams`.**

**Scroll behaviour:** Next.js no longer overrides `scroll-behavior: smooth` during navigation. Add `data-scroll-behavior="smooth"` to `<html>` to restore the old behaviour.

**Metadata:** under Cache Components, `generateMetadata` follows the same rules as components. If the page is otherwise fully prerenderable but metadata reads runtime data, that is an **error** — cache it or add a dynamic marker. `viewport` cannot stream, so keep it static.

**Tailwind 4:** `@import 'tailwindcss'` in the CSS entry plus `'@tailwindcss/postcss'` in `postcss.config.mjs`. No `tailwind.config.js` content array needed.

**Environment variables:** only `NEXT_PUBLIC_*` reach the client, inlined at build time. To read a server variable at runtime rather than build time, `await connection()` first. With a `src/` directory, `.env` files are still read from the project root, not from `src/`.

**Build output:** `size` and `First Load JS` were removed from `next build` output as inaccurate for server-driven architectures. Use `next experimental-analyze` (Turbopack) or Lighthouse instead.

## Dev tooling

`next dev` on 16.3+ maintains the managed block in `AGENTS.md` and `CLAUDE.md`. Do not delete it — it is regenerated, and committing it alongside your work keeps the tree clean. Opt out with `agentRules: false`.

An MCP server is exposed at `/_next/mcp` offering route listings, server logs, and compilation diagnostics. Browser console output is forwarded to the terminal.
